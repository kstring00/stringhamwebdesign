# Pre-launch audit — 2026-09-13

Every route, layout, component and public asset in the repo, opened and read,
not judged by appearance. Findings by section, what was fixed on the
`audit/prelaunch` branch, and what needs you. Fixes are in nine commits on that
branch; nothing is merged.

Verification at the end of the audit: `npm run build` clean, `npm run lint` 0
errors / 14 warnings (all pre-existing hook-dependency notes), all fourteen
browser checks passing against a production build, Lighthouse mobile 89–95 on
the five main pages with best practices and SEO at 100 everywhere.

## Part 1 — Stale code hunt

### 1. Routes and the shell they render

Twelve public page routes, three portal pages, seventeen API routes. Every
public page renders `app/Header.tsx` and `app/SiteFooter.tsx` through the root
layout's children; there is one layout (`app/layout.tsx`). The portal pages
render their own shell on purpose (a private app, not the marketing site) and
are excluded from crawling. Two routes had no shell: `/start`, which is a
redirect and never paints, and `/transmission-demo`, a public component demo
with no metadata — **removed**.

**No route was rendering an older shell.** The external audit's suggestion
did not reproduce from source: the crawl of all seventeen public pages
confirms the same seven header items (Home / About / Portfolio / Resources /
Pricing / Portal / Start a Project) and the same footer (League City line,
Site / Clients / Contact columns, dynamic © year, Privacy policy link) on every
one.

### 2. Nav, Header, Footer variants

Exactly one of each: `app/Header.tsx`, `app/SiteFooter.tsx`, with the item
list in `app/data/nav.ts` feeding both. Nothing to consolidate.

### 3. Hash anchors

Three in the codebase, all resolving: `#how` on /about, `#questions` on
/pricing, `#needs-you` in the portal admin. **No links to `/#timeline`,
`/#pricing` or `/#quick-contact` exist anywhere.** A `quick-contact` id is
defined but nothing links to it; harmless.

### 4. Placeholder markers

| Marker | Hits | Outcome |
|---|---|---|
| `PLACEHOLDER`, `[TECH]`, `lorem`, `TODO`, `FIXME`, `project-04` | none in source | — |
| `coming soon` | `app/work/[slug]/page.tsx:141` "Screenshot coming soon"; `app/work/ProjectUI.tsx:80` "Preview coming soon" | **removed** with the dead branches that showed them |
| `being finalized` | none | — |
| "Project 04" | `PendingProjectCard` on /work — the "Yours here / PENDING" slot | **removed** |

Remaining `placeholder` hits are HTML input placeholders and comments saying
there are none.

### 5. One project list

`app/data/projects.ts` is the only source. The homepage "Selected work", the
/work index, every case study, the previous/next links and the sitemap all
read from it, so a status changed there changes everywhere. **The
LIVE / LAUNCHING SOON disagreement cannot recur**: the `LAUNCHING SOON` value
was removed from the type, nothing had used it.

The set is five, not three: With Little, Common Ground, BCBA Prep, Lake City
Self Storage, and GrowthGains (added on 2026-09-12 at your request, after the
brief that lists three was written). **Lake City has real content** — two
real screenshots, a live URL and full copy — so it stays. Its status is
`CASE STUDY` while it carries a "Visit site" link to a Vercel preview domain;
see *Needs you*.

### 6. Design system on /work and case studies

Same tokens, same fonts, same palette (navy `#0d1b26`/`#183147`, cream
`#f5f0e8`, the golds) as /about and /pricing. Not an older design. What *was*
older: `work.module.css` still carried the entire previous case-study layout
(`detailHero`, `contentSection`, `twoCol`, `screenshotGrid`…) that
`CaseStudyCompact` replaced. Every rule no component references was removed
(2.6 KB of dead CSS), verified by computing class usage across every `.tsx`.

### 7. Unused code, deleted

- `app/BottomCapture.tsx` + css, `app/RetroCRT.tsx` + css,
  `app/Shoreline.tsx` + css — imported by nothing.
- `app/api/capture/route.ts` — its only caller was BottomCapture.
- `app/transmission-demo/page.tsx` — see §1.
- `PendingProjectCard`, `ProjectMedia`, `canVisitProject` — never used.
- A sign-in handler and two state hooks left in `PortalClient` after sign-in
  moved to `PortalRouter`; an unused type import in `TransmissionSubmit`.
- `public/selected-work/` — six PNGs, 16 MB, referenced nowhere.
- `public/about/portrait-placeholder.svg`, `public/hero-crt/` — orphaned.

No commented-out sections found.

**Over 300 KB:** only `pricing/close-forest.webp` (412 KB), and only the
desktop variant — phones get the 116 KB one. Acceptable; flagged.

**`/hero-crt/*.png` → WebP:** done, at 1600px (nothing displays them wider
than ~800px, so 2x), moved into each project's folder. No PNG fallback kept:
every browser this site targets decodes WebP.

**next/image:** not used anywhere, by design — every image is a plain `<img>`
with explicit `srcSet`/`sizes` on heroes and, after this audit, explicit
`width`/`height` on every project image so nothing shifts (CLS is 0 on all
five main pages). The lint rule for it is turned off with that reason
recorded. Migrating would add Vercel image-optimisation cost for little gain
at these sizes; recommended only if you later add many large photos.

**Fonts:** Cormorant Garamond (300, normal + italic) and Inter (variable),
both self-hosted by `next/font` at build — no request leaves the visitor's
browser. Portal CSS asks for Cormorant 400 in two places, which is not
loaded; the browser synthesises it. Cosmetic, portal only, not changed.

**Scripts:** only the app bundle and, once you enable it, Microsoft Clarity
(after load, never on the portal). Nothing else.

## Part 3 — Also done

- **`npm run lint` was broken** (`next lint` no longer exists in Next 16).
  It now runs ESLint directly with Next's own rules and the React Hooks rules.
  `eslint-config-next` and `typescript-eslint` cannot be used because both
  refuse TypeScript 7, this repo's compiler; TypeScript is parsed with Babel
  instead. Three rules are deliberately off, each with its reason in
  `eslint.config.mjs`.
- **Homepage accessibility 93 → 100**: eyebrow contrast, a brand link whose
  aria-label did not contain its visible text, a `<div aria-label>`.
- **Five legacy check scripts** had defects of their own (hardcoded port,
  stale expectations, a hang on lazy images). Fixed; details in
  `scripts/README.md`.
